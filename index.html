1. 先看整体流程：编译器到底在忙什么

不要一开始就陷进 FIRST、FOLLOW、LR 项目集。先把它们放回编译器流水线里。

词法分析把字符流切成 token。工具核心是正则表达式、正则文法、DFA/NFA。
语法分析判断 token 序列是否符合文法，并构造语法树或分析动作。
语义分析检查静态语义：类型、声明、作用域、数组下标、过程调用等。
中间代码生成与机器无关的表示，例如三地址码、四元式、AST。
优化与生成先做机器无关优化，再做和目标机器有关的代码生成与优化。

把一行代码走一遍

用 x = a + b * 3; 看流水线会更清楚：

  1. 词法分析先把字符切成 id(x)、=、id(a)、+、id(b)、*、num(3)、;。
  2. 语法分析确认它是“赋值语句”，右边是“加法表达式”，加法右侧又是“乘法表达式”。
  3. 语义分析检查 x、a、b 是否声明，类型能不能参与 + 和 *。
  4. 中间代码可能生成 t1=b*3、t2=a+t1、x=t2。
  5. 优化可能发现某些临时变量可删，后端再把它翻译成具体机器指令。
学习重点每一章其实都在解决“当前表示不够适合下一步”的问题：字符不适合语法分析，所以变 token；语法树不适合机器执行，所以变中间代码；中间代码还不贴近硬件，所以后端生成目标代码。

前端 Frontend

前端负责“读懂源程序”，和源语言相关，和目标机器无关。词法分析、语法分析、语义分析、中间代码生成都属于前端核心工作。

后端 Backend

后端负责“让机器执行”，和目标机器相关，和源语言弱相关。它处理 IR 优化、指令选择、寄存器分配、机器相关优化和目标代码生成。

初学者记法：前端像读者，负责理解代码；后端像工厂，负责把理解后的含义加工成目标机器能跑的东西。

2. 文法、CFG 与语言：先把术语拆开

语法分析以前，最重要的是理解“语言是集合，句子是集合里的元素”。

术语初学者解释常见坑
终结符 最终会出现在程序里的符号，例如 id、+、if。 终结符不能再被产生式展开。
非终结符 语法类别，例如 E、T、stmt。 它是“中间变量”，需要继续推导。
句型 从开始符号推导出来的任意符号串，可以含终结符和非终结符。 句型不一定是完整句子。
句子 只由终结符组成的句型，是语言集合中的一个元素。 只要还含非终结符，就不是句子。
推导与规约 推导是从左部替换成右部；规约是反过来，把右部收回左部。 => 是推导，<= 是规约，不能混用。
短语、直接短语、句柄 语法树某棵子树的叶子是短语；树高为 1 的子树叶子是直接短语；最左直接短语是句柄。 自底向上分析的关键就是识别句柄。

CFG（上下文无关文法）到底是什么

CFG 是 Context-Free Grammar 的缩写，中文通常叫“上下文无关文法”。编译原理里的语法分析，默认讨论的核心对象基本就是 CFG。

形式定义

一个 CFG 通常写成四元组 G=(V, T, P, S)：

  • V：非终结符集合
  • T：终结符集合
  • P：产生式集合
  • S：开始符号

“上下文无关”的含义

产生式左边只能是一个非终结符，例如 A → α。这表示无论 A 出现在什么上下文中，都可以按这条规则替换。

E → E + T | T
T → T * F | F
F → (E) | id
为什么编译器需要 CFG：正则表达式/DFA 适合处理 token 这种局部格式；CFG 能描述表达式嵌套、括号匹配、语句块等递归结构。LL、LR、SLR、LR(1)、LALR 这些分析方法，都是围绕 CFG 的不同分析策略。
概念适合描述典型位置
正则文法 / 正则表达式标识符、数字、关键字、运算符等 token 格式词法分析
CFG / 上下文无关文法表达式、语句、括号嵌套、程序结构语法分析
属性文法 / SDD / SDT在 CFG 结构上附加类型、地址、代码生成等语义信息语义分析与中间代码生成

乔姆斯基文法分类：知道层级，不用死背名字

复习资料里提到 0 型、1 型、2 型、3 型文法。考试里最常用的是 2 型 CFG 和 3 型正则文法，理解它们分别服务于语法分析和词法分析即可。

类型常见名称产生式限制编译原理里的典型用途
0 型无限制文法限制最少，表达能力最强理论背景，复习中通常不展开
1 型上下文有关文法产生式改写会受上下文影响了解即可
2 型上下文无关文法 CFG左部是单个非终结符 A表达式、语句、程序结构；LL/LR 分析的基础
3 型正则文法右线性或左线性描述 token；与正则表达式、有限自动机等价
包含关系：正则文法能描述的语言也能用 CFG 描述，但 CFG 能多描述括号匹配、表达式嵌套等递归结构。词法分析一般用正则工具，语法分析一般用 CFG。

文法题到底在问什么

文法题的目标不是自然语言描述，而是给出一组规则：能够生成所有合法串，同时排除非法串。

例：生成语言 L={anbn | n≥0}

核心关系是 a 和 b 的数量相等，且所有 a 在前、b 在后。可以让递归每次同时增加一个 a 和一个 b：

S → aSb | ε

推导 aabb：S ⇒ aSb ⇒ aaSbb ⇒ aabb。这里 ε 负责停止递归。

句子与句型的判断

aaSbb 是句型，因为还有非终结符 S；aabb 是句子，因为全是终结符。

最左推导、最右推导和规约的对应关系

自顶向下

从开始符号出发，不断替换非终结符，常用最左推导。LL 分析就是典型的自顶向下分析。

自底向上

从输入串出发，不断把句柄规约成非终结符。LR 分析常说的规范规约，就是最左规约，它对应最右推导的逆过程。

二义性文法

如果同一个句子能对应两棵不同的语法树，或者有两个不同的最左推导/最右推导，这个文法就是二义性的。

考试提醒：“判断任意文法是否二义”总体上不可判定；具体题目通常会给出一个句子，再通过两棵语法树或两条不同推导证明二义性。

3. 语言题构造：约束类型与文法选择

语言构造题可以先观察核心约束：有些题主要限制开头、结尾或局部格式，有些题主要维护数量相等或嵌套关系。这是做题时的观察方法，不是严格的理论分类。

格式约束

只关心开头、结尾、某些位置或局部禁忌，不需要记住任意远处的数量关系。常用“前缀 + 中间 + 后缀”拆。

不是以 0 开头的奇数
一位：O
多位：N D* O

O={1,3,5,7,9}，N={1..9}，D={0..9}。

数量/配对约束

左右数量相关、括号匹配、嵌套结构，通常要用递归在生成左边时“预约”右边。

a^n # b^n
S → aSb | #

每套一次递归，就同时增加一个左侧 a 和一个右侧 b。

边界提醒：这些名称只是帮助做题的经验标签。一个文法可以把格式约束拆成很多非终结符，例如“奇数字”“非零数字”“任意数字串”，这不代表它变成了数量配对问题；判断关键仍然是核心约束是否要求远距离数量相等或递归嵌套。

语言题万能观察模板

  1. 写例子。先写几个合法串和非法串，避免一上来就套产生式。
  2. 找核心约束。限制开头？结尾？数量？顺序？还是嵌套？
  3. 选构造方式。位置/格式限制通常拆成“开头 + 中间 + 结尾”；数量相等或嵌套通常用递归一层层包。
  4. 验证文法。写出产生式后，用几个例子推导，检查是否多生成或漏生成。

分层练习

练习 1：所有以 a 开头、以 b 结尾的字符串展开答案收起答案

这是格式约束。若字母表为 {a,b,c}，中间可以是任意多个 a/b/c。

S → aMb
M → aM | bM | cM | ε
练习 2：所有二进制偶数展开答案收起答案

二进制偶数最后一位必须是 0。如果允许数字 0 本身：

S → B0
B → 0B | 1B | ε

若题目额外要求“不允许前导 0”，再把多位数的第一位限制为 1。

练习 3：所有长度至少 2 的十进制数字串展开答案收起答案

这是纯长度格式约束。设 D 表示任意数字。

S → DDT
T → DT | ε
D → 0 | 1 | 2 | ... | 9
练习 4：所有不包含 00 的二进制串展开答案收起答案

这是格式约束里的“局部禁忌”：看到 0 后，下一个不能再是 0。

S → 1S | 0A | ε
A → 1S | ε

A 表示“刚刚生成了 0，下一步只能结束或生成 1”。

练习 5：a^n b^n展开答案收起答案

这是典型数量配对约束。若 n≥0：

S → aSb | ε

若 n≥1，可以用 S → aSb | ab。

练习 6：a^n b^n c^m展开答案收起答案

只有 a 和 b 数量相关，c 只是后面任意多个。

S → TC
T → aTb | ε
C → cC | ε
练习 7：括号匹配展开答案收起答案

括号匹配既可以嵌套，也可以并列。

S → (S)S | ε

(S) 处理嵌套，后面的 S 处理并列，例如 ()()。

练习 8：回文串展开答案收起答案

回文是左右对称，所以两边一起长。若字母表为 {a,b}：

S → aSa | bSb | a | b | ε

a/b 处理奇数长度中心，ε 处理偶数长度中心。

4. 词法分析：从字符到 token

词法分析是编译器的第一道关：它不理解复杂语法，只负责把输入切成“单词”。

关键字 标识符 常数 运算符 分界符
正则表达式描述单词模式，例如标识符、整数、注释。
NFA人更容易画，可有多条选择，也可有空边。
DFA计算机更容易执行，每个状态读一个字符只有确定去向。
最小化 DFA合并等价状态，减少状态数。
识别 token扫描输入，进入终态就接受一个单词。

一个小例子

正则式 a(b|c)* 表示：以 a 开头，后面可以跟任意多个 b 或 c。

可接受：a, ab, ac, abbcc
不可接受：b, ba, aa

NFA 到 DFA：子集构造法的直觉

一个 NFA 状态读入同一个字符可能到多个状态。DFA 不允许“不确定”，所以把“一组 NFA 状态”当成 DFA 的一个新状态。

1
先求初态的空闭包，作为 DFA 初态。
2
对每个输入字符，计算当前集合能到达的所有 NFA 状态。
3
再对结果求空闭包，得到新的 DFA 状态。
4
重复直到不产生新集合；只要集合里含 NFA 终态，这个 DFA 状态就是终态。

手算自动机的稳定流程

自动机题最怕状态名写乱。建议把“状态集合”当成表格里的新状态，而不是急着画图。

子集构造法表格模板
DFA 状态NFA 状态集合读 a 后读 b 后
A{0,1}{2}{1,3}
B{2}......

表里出现的新集合再起一个 DFA 状态名。最后再画状态图，会比边算边画稳很多。

最小化提醒先删不可达状态，再按“终态/非终态”初分组。两个状态是否能合并，看它们读每个输入后是否跳到同一类组。

正则表达式、正则文法和自动机互转

词法分析这一章的几个工具本质上在描述同一类语言：正则语言。题目常在正则表达式、右线性文法、状态转换图、DFA/NFA 之间来回转换。

正则表达式优先级

一般按 *、连接、| 的顺序从高到低。括号可以改变优先级。

ab* | c
表示：a 后跟若干 b，或者 c
不是：(ab)* 或 c

右线性文法

产生式右部最多一个非终结符，并且非终结符在最右边，例如 A → aB | b。它适合直接转成状态图。

A → aB
B → bB | ε
转换方向基本做法
右线性文法 → 状态图每个非终结符看作一个状态；A→aB 画 A --a→ B；终结产生式连向终态。
状态图 → 右线性文法每条边写成产生式；从终态补空产生式或终结产生式。
正则表达式 → NFA按并、连接、闭包递归构造 NFA；再确定化、最小化。
NFA → DFA用子集构造法，把 NFA 状态集合当作 DFA 状态。

DFA/NFA 的正式定义与错误处理

DFA 通常写成五元组 M=(S, Σ, δ, s0, F)：状态集合、输入符号集合、转移函数、初态、终态集合。NFA 允许一个状态在同一输入下到达多个状态，也允许 ε 空边。

表示方法

DFA 可以用转移函数、转移矩阵或状态转换图表示。做题时矩阵适合查表，状态图适合理解路径。

词法错误处理

词法阶段能发现非法字符、未闭合注释等局部错误；关键字拼写成标识符、类型不匹配等问题通常要等语法或语义阶段处理。

常见题型：正则表达式 → NFA → DFA → 最小化 DFA；状态转换图 → 右线性文法；右线性文法 → 状态转换图。

本章练习

练习：写出 token 序列

输入串：if count<=10 then count:=count+1。设 if、then 为关键字，<= 为关系运算符，:= 为赋值号。

答案展开答案收起答案

一种 token 序列为：(if,-)、(id,count)、(relop,<=)、(num,10)、(then,-)、(id,count)、(assign,:=)、(id,count)、(addop,+)、(num,1)。

关键字通常一符一类；标识符和常数通常按种类编码，并在属性值里保存具体名字或数值。

练习：由正则式写右线性文法

为正则式 a(a|b)*b 写一个右线性文法。

答案展开答案收起答案

可取文法：

S → aA
A → aA | bA | b

S → aA 保证首字符为 a，A 中的递归产生中间的任意 a/b 串，最后用 A → b 保证以 b 结束。

练习：NFA 子集构造法

NFA 状态为 q0、q1，初态 q0，终态 q1。转移：q0 --a--> q0、q0 --a--> q1、q1 --b--> q1。构造 DFA 转移表。

答案展开答案收起答案
DFA 状态NFA 状态集合读 a读 b是否终态
A{q0}BD否
B{q0,q1}BC是
C{q1}DC是
D∅DD否

含有 NFA 终态 q1 的集合都是 DFA 终态；空集合通常作为死状态补全转移。

5. LL(1)：自顶向下的预测分析

LL(1) 的目标是：只向前看 1 个输入符号，就能决定用哪条产生式。

为什么要改造文法

递归下降分析会直接按产生式写程序。若文法有左递归，例如 A → Aα | β，程序会一进来又调用自己，陷入死循环。

两类常见改造

消除左递归，避免无限递归；提取左公因子，避免看到同一个前缀时无法选择产生式。

消除直接左递归

如果有：

A → Aα | β

改成：

A → βA'
A' → αA' | ε

FIRST、FOLLOW、SELECT 的分工

集合它回答的问题做题提示
FIRST(α) 串 α 最前面可能出现哪些终结符？ 如果 α 能推出空串，要把 ε 继续向后传。
FOLLOW(A) 非终结符 A 后面可能紧跟哪些终结符？ 开始符号的 FOLLOW 要含结束符 # 或 $。
SELECT(A→α) 看到哪个输入符号时，可以选择这条产生式？ 判断 LL(1) 看“同左部产生式”的 SELECT 是否两两不交。

LL(1) 做题模板

1
检查并消除左递归，必要时提取左公因子。
2
求每个非终结符和产生式右部的 FIRST 集。
3
求 FOLLOW 集，注意开始符号和能推出 ε 的情况。
4
求 SELECT 集，判断同左部产生式是否互不相交。
5
构造预测分析表：行是非终结符，列是终结符或结束符。

一个完整的 LL(1) 小例子

设文法：

S → aA | b
A → c | ε
  1. FIRST(aA)={a}，FIRST(b)={b}，所以 S 的两条产生式开头不冲突。
  2. FIRST(c)={c}，FIRST(ε)={ε}。
  3. 因为 A 出现在 S → aA 的末尾，所以 FOLLOW(S) 要传给 FOLLOW(A)；开始符号 S 的 FOLLOW 有 #，所以 FOLLOW(A)={#}。
  4. SELECT(A→c)={c}；A→ε 能推出空，所以 SELECT(A→ε)=FOLLOW(A)={#}。
为什么这就是 LL(1)同一个左部的产生式 SELECT 集两两不相交：{a} 和 {b} 不交，{c} 和 {#} 不交。看到 1 个输入符号就知道选哪条。

S_ 文法、q_ 文法与 LL(1) 文法

复习资料里把预测分析文法分成几个层次。它们都是为了保证分析器看到当前输入符号时能唯一选择产生式。

名称核心条件局限
S_ 文法每个候选式以终结符开头，同一非终结符的各候选式首终结符不同，且通常不含空产生式。限制强，不能覆盖很多常见 CFG。
q_ 文法候选式要么是空串，要么以终结符开头；同左部候选式 SELECT 不相交。仍不允许右部以非终结符打头。
LL(1) 文法允许右部以非终结符打头，只要同左部各产生式 SELECT 集两两不交。比前两者强，但仍不能处理所有 CFG。

递归预测分析、表驱动预测分析与错误处理

递归预测分析

为每个非终结符写一个过程，过程内部根据当前输入符号和预测分析表选择产生式。它直观，但依赖调用栈。

非递归预测分析

用显式分析栈和预测分析表模拟推导，也叫表驱动预测分析。栈顶是终结符就匹配，栈顶是非终结符就查表展开。

预测分析错误处理：常见错误包括栈顶终结符和当前输入不匹配，以及预测分析表对应项为空。恐慌模式会跳过输入符号，直到遇到同步词法单元，再尝试恢复分析。
最容易丢分：SELECT 的参数是“产生式”，不是单个非终结符；FOLLOW 的传播要看产生式右侧位置，不是凭感觉补符号。

6. 自底向上：移进-归约与 LR 家族

自底向上分析不从开始符号出发，而是从输入串出发，把能规约的部分一步步收回去。

移进

把下一个输入符号压入栈。可以理解成“先收集证据”。

归约

当栈顶形成某个产生式右部时，把它替换成产生式左部。这个右部就是当前要找的句柄。

算符优先分析

算符优先文法用终结符之间的优先关系帮助找素短语边界。FIRSTOP 和 LASTOP 用于构造优先关系表。

不要误会：+ <· * 不是说“先算 + 再算 *”，而是说在分析过程中，遇到 + 后面跟 * 时可以继续移进，二者之间不该先规约。

算符优先分析补充

算符优先分析只看终结符之间的优先关系，用来确定最左素短语的边界。它实现简单，但对文法限制较多，错误发现也不如 LR 系列精细。

概念说明
算符文法产生式右部不能出现相邻非终结符，便于用终结符关系定位归约边界。
FIRSTOP(X)从 X 推导出的句型中，最左边可能出现的终结符集合。
LASTOP(X)从 X 推导出的句型中，最右边可能出现的终结符集合。
优先矩阵记录终结符之间的 <·、=·、·> 关系，用于移进或归约。
优先函数用函数值代替矩阵，减少空间，但不是所有优先关系表都能转成优先函数。

LR 分析器的四件套

组件作用
状态栈记录当前分析器处于哪个自动机状态。
符号栈记录已经移进或归约得到的文法符号。
ACTION 表根据状态和输入终结符决定移进、归约、接受或报错。
GOTO 表归约出非终结符后，决定状态栈跳到哪里。

LR(0) 项目：点的位置代表进度

E → ·E + T 待约项目：还没开始识别右部
E → E · + T 移进项目：下一个期待 +
E → E + T · 归约项目：右部已经识别完成
增广文法 给原开始符号加一个新开始符号，例如 S' → S，方便定义唯一接受状态。
CLOSURE 如果点后面是非终结符，就把它的产生式也加进项目集。
GOTO 项目集读入某个符号后，点向右移动，再求闭包。
活前缀 不会越过句柄右端的栈内容前缀，LR 自动机识别的就是活前缀。

LR 项目集构造流程

LR 表看起来复杂，其实是把“栈顶现在可能是什么进度”整理成自动机状态。

  1. 先编号产生式。后面归约时写 r1、r2 才不会乱。
  2. 加增广产生式。例如 S' → S，接受动作只来自 S' → S·。
  3. 从 S' → ·S 求闭包。点后有非终结符，就把它的候选产生式都加进来。
  4. 对每个文法符号求 GOTO。点越过该符号，得到新项目集；新项目集继续求闭包。
  5. 填表。点后是终结符填移进，点在末尾填归约，点后是非终结符填 GOTO。
为什么会冲突同一个状态、同一个输入符号上，如果既能移进又能归约，就是移进-归约冲突；如果能按两条产生式归约，就是归约-归约冲突。

LR 分析过程与错误处理

LR 分析运行时反复查看“状态栈顶 + 当前输入符号”，再根据 ACTION/GOTO 表动作。

动作含义栈变化
移进 sj读入当前终结符，并进入状态 j。输入符号入符号栈，状态 j 入状态栈。
归约 ri按第 i 条产生式 A→β 归约。弹出 |β| 个符号和状态，再按 GOTO 压入 A 和新状态。
接受 acc输入串分析成功。通常来自增广产生式 S'→S·。
报错ACTION 表项为空或无合法动作。可用恐慌模式跳过输入或弹栈恢复。
二义性文法与 LR：二义性文法不一定完全不能用。实际工具常通过规定优先级、结合性或默认移进/归约策略消解冲突，但考试中要先说明冲突在哪里。

LR 家族的区分方式

方法归约动作填写依据特点
LR(0) 只要项目形如 A→α·，就在所有输入符号列填归约。 最简单，但很容易产生冲突。
SLR(1) 只在 FOLLOW(A) 中的输入符号列填 A→α 的归约。 用 FOLLOW 缩小归约范围，仍可能不够精细。
LR(1) 项目自带展望符，只在展望符对应列归约。 分析能力强，但项目集和表可能很大。
LALR(1) 先构造 LR(1)，再合并同心项目集。 规模接近 SLR，能力接近 LR(1)，常用于实际工具。
包含关系与分析能力：通常记作 LR(0) ⊂ SLR(1) ⊂ LALR(1) ⊂ LR(1)，分析能力从左到右增强。

增广文法：

0. S' → S
1. S  → A a

答案展开答案收起答案

从初始项目集读入 b 后，会到达含 S → b · 和 A → b · 的项目集。LR(0) 会在所有终结符列同时填 r2 和 r3，因此出现归约-归约冲突。

7. 语法制导翻译：把“语法结构”变成“语义动作”

语法分析只知道结构对不对，语法制导翻译进一步把结构用于类型检查和中间代码生成。

SDD：语法制导定义

在上下文无关文法上附加属性和语义规则。它偏“定义”，说明每个属性怎么算。

SDT：语法制导翻译方案

把语义动作嵌入产生式右部。它偏“执行”，说明分析到哪里时做什么。

综合属性和继承属性

属性值从哪里来适合什么场景
综合属性 通常由子节点或自身信息计算，沿语法树向上传。 表达式求值、类型合成、生成临时变量。
继承属性 通常由父节点或左侧兄弟节点传来，沿语法树向下或向右传。 声明类型向变量列表传递、数组宽度、上下文信息。

S-属性定义与 L-属性定义

S-属性定义

只有综合属性。天然适合自底向上分析，因为规约时子节点已经在栈上。

L-属性定义

允许继承属性，但右部符号的继承属性只能依赖左部父节点或它左边的兄弟节点，适合从左到右翻译。

理解方式：SDD 像公式表，SDT 像把公式变成程序。属性依赖图决定这些公式能不能按某个顺序算出来。

属性文法为什么会出现在编译原理里

语法树只能表达结构形态，但编译器还需要知道类型、地址、宽度、临时变量、跳转目标等信息。这些信息就用属性挂在文法符号上。

表达式翻译的常见属性

E.place 可以表示表达式结果存在哪里；E.code 可以表示为了计算它要生成哪些三地址码。

E → E1 + T
E.place = newtemp()
E.code = E1.code || T.code || gen(E.place = E1.place + T.place)
声明翻译的常见属性

T.type 记录类型，T.width 记录宽度，声明变量时把 name/type/offset 填入符号表，然后更新 offset。

依赖图、拓扑排序与翻译实现

属性值之间有依赖关系：如果属性 b 的计算需要属性 a，就画一条 a → b。属性求值必须按依赖方向进行。

依赖图

依赖图没有环时，可以按拓扑序计算属性；如果有环，说明属性定义互相等待，正常求值无法完成。

拓扑排序

每次选择入度为 0 的节点，计算后删除它和它的出边。这个顺序就是属性求值顺序。

实现场景常用方式
S-属性定义自底向上翻译规约时子节点属性已经在栈上，直接用栈操作计算父节点属性。
L-属性定义自顶向下翻译继承属性从左向右传递，语义动作要放在能拿到所需属性的位置。
非递归预测分析中翻译把语义动作作为特殊符号压栈，弹出时执行。
自底向上翻译 L-属性常引入标志性非终结符，让动作在合适时机触发。

8. 中间代码与符号表：编译器的“中间账本”

中间代码让前端和后端解耦；符号表让编译器记住名字、类型和作用域。

AST

抽象语法树保留程序结构，去掉括号、分号等不必要细节。

逆波兰式

运算符放在操作数后面，例如 a b + 表示 a + b。

三地址码

每条语句最多三个地址，形如 t1 = a + b。

四元式

四元式是三地址码的常见实现形式，通常写成：

(op, arg1, arg2, result)

表达式

x = a + b * c

三地址码与四元式

t1 = b * c (*, b, c, t1)
t2 = a + t1 (+, a, t1, t2)
x = t2 (=, t2, -, x)

中间代码题的落笔顺序

  1. 表达式：先按优先级和括号拆。每拆一个运算就生成一个临时变量。
  2. 数组引用：先算偏移地址，再取值。多维数组要注意行优先/列优先和每维宽度。
  3. 布尔表达式：可以用数值表示，也可以用控制流表示。控制流表示更常见，会生成条件跳转。
  4. 控制语句：先标出入口、真出口、假出口、下一条指令，再回填跳转地址。
if 语句的直觉
if B then S1 else S2

先翻译 B。如果 B 为真，跳到 S1；如果 B 为假，跳到 S2。S1 执行完通常还要跳过 S2，到整个 if 的下一条指令。

类型表达式、类型等价与类型检查

语义分析不仅要生成代码，还要判断程序含义是否合理。类型系统相关题目常围绕类型表达式、类型等价、类型转换和类型检查展开。

概念要点
类型表达式用结构化方式表示类型，例如数组、指针、函数、记录类型等。
结构等价两个类型结构相同就认为等价。
名字等价只有由同一个类型名声明出来，才认为等价。
类型综合由子表达式类型推出父表达式类型，例如整数加整数得到整数。
类型推断根据上下文约束反推出表达式或变量的类型。
类型转换必要时插入显式或隐式转换，但不能改变语言规定的语义。

数组、布尔表达式和控制流翻译

数组地址计算

数组引用翻译的核心是算偏移。多维数组要看行优先或列优先，并使用每一维的宽度。

addr(A[i]) = base(A) + i * width

布尔表达式翻译

可用数值表示，也可用控制流表示。控制流表示会生成条件跳转，并维护 truelist、falselist。

if x < y goto _
goto _
结构翻译关注点
if / if-else真出口、假出口、then 后跳转、整个语句的下一条指令。
while循环入口、条件为真进入循环体、循环体结束回到入口、条件为假跳出。
switch集中测试表达式，按 case 值跳转，必要时生成 case 指令或跳转表。
过程调用先为每个实参生成 param，再生成 call p, n，返回值放临时变量。
回填 backpatching：先生成跳转目标未知的指令，把这些指令编号放进链表；等目标地址确定后，再统一把空目标填上。

符号表记录什么

信息用途
名字 name标识符叫什么。
类型 type检查赋值、表达式、参数是否类型匹配。
偏移 offset确定变量在活动记录或内存中的位置。
宽度 width为数组、结构体、过程局部变量分配空间。
作用域/嵌套层次处理重名变量和过程声明。

符号表组织结构与作用域

课件第 8 章把符号表单独成章。符号表不是简单名单，而是编译各阶段共享的名字信息数据库，核心操作是 insert 和 lookup。

组织方式特点适合场景
线性表结构直观，插入简单，查找可能慢。符号数量少或教学例题。
有序表查找可加速，但插入维护顺序有成本。查找次数远多于插入次数。
散列表平均查找和插入效率高，实际编译器常用。大量标识符和频繁查询。
字符串表 + 符号表长标识符统一存入字符串表，符号表保存指针或索引。节省空间，避免反复存储名字字符串。

作用域与最近嵌套原则

查找名字时先查当前块，再沿外层块向外查；找到的第一个同名声明就是该引用对应的声明。

多表或统一表

可以为每个作用域建一张表，也可以在统一符号表中记录块号、层次或链表关系。进入作用域插入，退出作用域删除或恢复外层表。

声明语句翻译的核心：不断更新当前偏移量，把每个变量的名字、类型、宽度、偏移填进符号表。

9. 运行时存储组织：程序运行时数据放在哪里

前面几章关注“怎么分析和翻译程序”，运行时存储组织关注“翻译后的程序运行时如何管理变量、过程调用和内存”。

源语言特征会影响存储策略

编译器必须根据语言特征决定何时、怎样给名字分配内存地址。能在编译时决定的是静态策略，必须到运行时才能决定的是动态策略。

语言特征对存储组织的影响
静态作用域 / 动态作用域静态作用域按程序文本嵌套找声明；动态作用域按调用链找最近活动声明。
递归过程同一个过程可能同时有多个活动记录，通常需要栈式存储分配。
动态数组或动态对象大小或生命周期运行时才确定，需要动态分配或堆管理。
参数传递方式影响活动记录中保存的是值、地址，还是返回时需要复制回实参。

静态存储分配

编译时就能确定数据对象的存储位置，运行时不再改变。适合全局变量、静态变量，以及不支持递归或动态大小对象的简单语言场景。

动态存储分配

运行时再分配空间，常见形式是栈式分配和堆式分配。递归调用、过程局部变量、动态对象通常依赖动态分配。

参数传递方式

方式做法效果
传值计算实参右值，把值放入形参单元。形参改变不影响实参。
传地址 / 传引用把实参地址传给被调过程。形参访问的是实参存储单元，修改会影响实参。
传值结果调用时像传值，返回时把形参最终值复制回实参。兼有传值和复制回写，注意多个参数别名时可能产生顺序问题。

运行时内存区域

区域保存什么特点
代码区目标代码通常只读或很少变化。
静态区全局变量、静态变量、常量等程序整个运行期间都存在。
栈区过程调用的活动记录、局部变量、返回地址等随调用进入和返回自动增长/回收。
堆区动态申请的对象生命周期不一定跟过程调用一致，需要运行时管理。

活动记录：一次过程调用的账本

每调用一次过程，运行时栈上通常会生成一个活动记录。它记录这次调用需要保存的局部状态。

活动记录常见内容

  • 实参或参数区
  • 返回值位置
  • 返回地址
  • 控制链/动态链
  • 访问链/静态链
  • 局部变量和临时变量

活动树与控制栈

活动树表示过程调用之间的父子关系；控制栈保存当前还没返回的活动记录。栈顶活动记录对应当前正在执行的过程。

调用序列、返回序列与非局部数据访问

概念说明
调用序列调用前执行的指令序列，例如计算实参、保存返回地址、建立新活动记录、转入被调过程。
返回序列过程结束时执行的指令序列，例如保存返回值、恢复调用者状态、释放活动记录、跳回返回地址。
控制链/动态链指向调用者的活动记录，用来恢复调用关系。
访问链/静态链指向静态外层过程的活动记录，用来访问嵌套作用域里的非局部变量。
是否需要访问链：如果语言不支持过程嵌套，非局部数据通常就是全局变量；如果支持过程嵌套，内层过程访问外层局部变量时就需要静态链或其他等价机制。

符号表和运行时存储的连接

符号表中的 type、width、offset 最终会服务于运行时寻址。编译器根据作用域和偏移信息，生成访问变量所需的地址计算代码。

堆管理：生命周期不跟调用栈同步的数据

堆用于保存动态申请的数据，对象生命周期可能超过创建它的过程调用。堆管理要处理空间申请、释放、碎片和可用块查找。

为什么需要堆

当数据对象大小或生存期无法按栈式“先进后出”管理时，就需要堆。例如动态创建的对象、链表节点、运行时长度数组。

复习关注点

理解堆和栈的区别即可：栈服务过程调用，堆服务动态对象；栈回收顺序固定，堆回收更复杂。

10. 代码优化：先整理逻辑，再适配机器

优化不是改变程序含义，而是在含义不变的前提下让代码更快、更小或更适合机器执行。

机器无关优化

发生在中间代码层，和具体 CPU 无关。常见方法有常量合并、常量传播、复制传播、公共子表达式删除、死代码删除、循环不变式外提。

机器有关优化

发生在目标代码阶段，依赖具体硬件。常见方法有寄存器分配、指令选择、指令调度、窥孔优化、缓存友好调整。

基本块与流图

基本块是一段只有一个入口、一个出口的连续代码。先把程序划分为基本块，再画基本块之间的控制流图，很多优化才有落点。

基本块划分算法

  1. 找入口语句。程序第一条语句是入口；跳转目标是入口；紧跟在跳转语句后面的语句也是入口。
  2. 形成基本块。每个入口到下一个入口之前的连续语句构成一个基本块。
  3. 画流图。如果一个基本块可能执行后进入另一个基本块，就画一条控制流边。

基本块内的语句要么从第一条开始顺序执行，要么整个块不执行；中间不会从外部跳入，也不会从中间跳出。

优化看见什么就想到它
公共子表达式删除同一个表达式重复计算，且中间变量没改变。
常量传播变量已经确定等于常量，把后续使用直接替换。
复制传播x = y 后，把后续 x 的使用替换为 y。
死代码删除计算结果再也没有被使用，或者不可达。
DAG 优化在基本块内部用 DAG 合并重复计算并保留依赖关系。

优化题的删除判断

优化最重要的底线是语义不变，所以不要只看某一行，要看这个值后面还会不会被用到。

例：公共子表达式
t1 = a + b
t2 = a + b
x = t1 * t2

如果中间没有修改 a 或 b，那么第二次 a+b 可以复用 t1，变成 t2=t1 或直接在后续使用 t1。

例：死代码
t3 = c + d
x = a + b

如果 t3 后面再也没有被使用，且计算它没有副作用，就可以删除。函数调用、输入输出这类可能有副作用的语句不能随便删。

出口活跃变量只有 d 和 e：

t1 := a + b
t2 := a + b
t3 := t2 * c
d := t1
e := d * c
答案展开答案收起答案

t2 与 t1 是同一公共子表达式，d 保存 t1 后，e 可直接由同一个值计算。可优化为：

t1 := a + b
d := t1
e := t1 * c

若题设说明 t3 在出口也活跃，则还需要保留 t3 := t1 * c 或让 t3 与 e 共享结果。

11. 代码生成：把中间代码落到目标机器

代码生成是编译的最后阶段，输入是中间代码和符号表信息，输出是等价且质量较高的目标代码。

输入

中间代码负责表达运算和控制流；符号表提供类型、宽度、偏移和运行时地址所需信息。

输出

目标代码可以是绝对机器代码、可重定位机器代码，也可以是汇编代码。课件中用汇编指令说明。

目标

生成语义等价的代码，同时尽量提高运行效率和代码质量，充分利用目标机器资源。

代码生成器设计中的核心问题

问题说明
指令选择为每条中间代码选择合适的目标机器指令。特殊指令可能让代码更短更快。
寄存器分配决定哪些值在某个程序点应该放入寄存器。
寄存器指派决定某个值具体放在哪个寄存器中。
计算顺序选择不同计算顺序可能需要不同数量的寄存器，影响装入/存储次数。
运行时地址根据符号表、活动记录和偏移信息生成变量访问代码。

从三地址码到目标指令

如果三地址语句是 x := y + z，一种朴素翻译是先把 y 装入寄存器，再加上 z，最后把结果存回 x。

LD R0, y
ADD R0, R0, z
ST x, R0

但真实代码生成器还要考虑：y 或 z 是否已经在寄存器中、x 后面是否还活跃、是否有更便宜的机器指令可用。

窥孔优化

窥孔优化是在目标代码上移动一个很小的窗口，检查短指令序列是否能被更短或更快的等价序列替换。

技术例子
冗余指令消除连续装入/存储后发现其中一条没有必要。
不可达代码删除无条件跳转后面、且没有标号可跳入的指令可以删除。
强度削弱用更便宜的运算替换昂贵运算，例如乘法换成移位或加法。
特殊机器指令用 INC 之类专门指令实现 a := a + 1。
代数化简删除 x+0、x*1 这类无效运算。
难点提醒：寄存器分配和指派通常是代码生成中最难的部分。寄存器少时，需要决定哪些值保留在寄存器，哪些值溢出到内存。

练习：窥孔优化

考虑目标指令片段：

MOV a, R0
MOV R0, b
MOV b, R0
ADD c, R0
MOV R0, d
答案展开答案收起答案

若 MOV R0, b 和 MOV b, R0 之间没有修改 b，且没有标号或别名副作用，第三条装回寄存器是冗余的。可改为：

MOV a, R0
MOV R0, b
ADD c, R0
MOV R0, d

窥孔优化的底线是等价：不能删除带标号的目标、不能跨越可能改变内存或寄存器含义的指令。

12. 做题路线：看到题目先归类

编译原理题通常不是靠背一句定义，而是靠稳定的解题步骤。步骤清晰，推导、填表和代码生成才不容易漏项。

题型 A：构造文法

先找语言的结构规律：长度关系、数量关系、嵌套关系、可重复片段。能拆成“前缀 + 中间 + 后缀”时，优先让非终结符负责递归生成。

题型 B：证明文法二义性

找一个具体句子，写出两条不同最左推导，或画出两棵不同语法树。不要只说“看起来有歧义”。

题型 C：DFA/NFA 转换与最小化

先确定化，再最小化。最小化时先按终态/非终态分组，再不断用不同输入符号能到达的组来细分。

题型 D：判断 LL(1)

消除明显左递归后，求 FIRST、FOLLOW、SELECT。只要同一非终结符的不同产生式 SELECT 集相交，就不是 LL(1)。

题型 E：构造 LR 分析表

先增广文法，再列 LR 项目，求 CLOSURE/GOTO，构造项目集 DFA。最后填 ACTION/GOTO 表，检查移进-归约或归约-归约冲突。

题型 F：中间代码生成

表达式题按运算优先级生成临时变量；控制流题盯住真出口、假出口、下一条指令；声明题盯住类型、宽度和 offset。

题型 G：运行时存储组织

活动记录题先写清楚保存哪些字段；非局部变量访问题先判断是否有过程嵌套，再考虑访问链/静态链；调用返回题区分调用序列和返回序列。

题型 H：类型检查与数组地址

类型题先判断结构等价还是名字等价；数组题先确定元素宽度和各维跨度，再生成偏移计算。

题型 I：代码生成

代码生成题先看三地址码，再按目标机器指令格式翻译；寄存器题关注哪些值还会被使用，窥孔优化题看短指令序列能否等价替换。

复习时按“输出物”训练

每类题都有明确输出物。训练时应完整写出对应产物，而不只停留在理解答案。

题型最终要交什么先检查什么
文法构造产生式集合是否多生成/漏生成字符串
LL(1)FIRST/FOLLOW/SELECT 和预测分析表同左部 SELECT 是否相交
LR项目集规范族、DFA、ACTION/GOTO 表是否有冲突，归约列是否填对
中间代码三地址码或四元式序列临时变量顺序和跳转目标
运行时存储活动记录布局、访问链、调用/返回序列作用域、调用关系和变量偏移
代码生成目标指令序列、寄存器使用、窥孔优化结果语义是否等价，装入/存储是否冗余

13. 易错点清单

这些点在原笔记里反复出现，适合考前单独过一遍。

句子 vs 句型 句子只能含终结符；句型可以含非终结符。
左递归会卡住递归下降 遇到 A → Aα 要先消除，再谈 LL 分析。
FOLLOW 集包含结束符 开始符号的 FOLLOW 一定包含 # 或 $。
SELECT 是产生式的集合 判断 LL(1) 比的是同左部各产生式的 SELECT 是否相交。
句柄是当前规约目标 自底向上分析最关键的问题是正确识别句柄。
LR(0) 归约太粗 LR(0) 对所有输入符号填归约，所以容易产生冲突；SLR 用 FOLLOW 收窄。
LR(1) 展望符更精细 LR(1) 项目带展望符，只在展望符列归约，所以能力强但表大。
FIRSTOP/LASTOP 不是运行顺序 它们服务于算符优先关系表，不等于“谁先归约”。
回填不是立刻知道目标 布尔表达式和控制流翻译里，跳转目标常先留空，等入口地址确定后统一填上。
类型等价规则要先看题设 结构等价和名字等价判断结果可能不同，题目没说明时不要自己混用。
访问链服务于静态嵌套 控制链记录谁调用了谁，访问链记录词法作用域外层是谁，二者不要混。
基本块入口别漏跳转后继 跳转目标是入口，跳转语句后面的第一条语句也可能是入口。
寄存器分配和指派不是一回事 分配决定哪些值放寄存器，指派决定具体放哪个寄存器。
窥孔优化必须等价 短指令序列可以替换，但不能改变寄存器、内存或控制流的可观察结果。
